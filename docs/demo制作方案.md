## 一·B、方法全景：阶段 / 部分 / 工作流 / 细节（★一级目标★）

> **一级目标**：demo 的首要任务**不是「罗列数字」**，而是让评审在 5 分钟内看懂——
> **这个方法由哪些阶段与部分组成、每部分内部怎么走、各自解决了什么问题、证据在哪里**。数字是支撑，**流程是主线**。

### B.1 四层骨架

| 层 | 内容 | 展示方式 | 数据来源 |
|---|---|---|---|
| **L0 场景与约束** | 灾后公网全瘫 · 海量突发 · 星上轻量（不增轮次/不增信令/计算轻） | 静态图文 + 参数卡 | `scenario_config.json`；`Agents.md §0` |
| **L1 三大机制（主线）** | ① 两步 RACH 接入　② HMAC 双根·假名轮换·哈希链认证　③ 星间预迁移切换 | **机理示意（明确标注）+ 真实数据回放** | 机理：`sim/protocol.py` / `.ns3_ref/leo_access.cc`；数据：`access_trace.csv` |
| **L2 支撑机制** | T8 业务感知提前量 · 生存优先调度（guard-channel + Kaufman-Roberts）· 失配兜底 rerach · 乒乓抑制 | **数据驱动（开关对照）** | `t8_comparison.json` · `priority_comparison.json` · trace 的 `service`/`pingpong`/`predict_mismatch` |
| **L3 验证体系** | 双轨互证 · 三阶段消融边际 · 敏感性可证伪 · 10 种子 CI · `run_id` 溯源 | 图表 + 溯源徽标 | 对照表 §2/§3/§3.1 · `ablation.json` · `敏感性分析*.json` · `多种子统计*.json` |

### B.2 每条机制的固定「四问」模板（页面按此组织）

| 问 | ① 两步 RACH 接入 | ② 星上认证 | ③ 预测式切换 |
|---|---|---|---|
| **何时触发** | 终端上电 / 失联后发起接入 | 接入信令到达星上，本地校验 | 预测 LOS 末端前 `ho_lead`（默认 20 s） |
| **内部怎么走** | 终端发预补偿 msgA（前导+数据）→ 星上回 msgB，**一次往返**（对照 Rel-17 四步：msg1→msg2→msg3→msg4） | 双根派生 → 假名轮换 → 哈希链推进 → MAC 截断 4 B 比对 → 计数器防重放 | 预测 → 选候选星 → 上下文**星间预推** → **先建后断** → 一次比对确认 → 失配则 rerach 兜底 |
| **输出什么** | 时延 **193.44 ms**、成功率 **0.7050**（对照四步 652.80 / 0.4455） | 拦截率 **0.8537**、漏检 0.1463（随泄露率单调 ≈1−share） | 切换总时延 **12.06 ms**（对照 381.0）；中断 0.02 ms；命中率 1.0 |
| **证据在哪** | 对照表 §5；`rel17_improvement.json` | trace `auth_result` 分布（见 B.3） | 对照表 §6；`ablation.json` 阶段 2 |

### B.3 ★阶段漏斗：真实事件驱动的「方法全链路」★（已验证，最强抓手）

以 `wenchuan_storm2`（ns-3，2026-09-23 批次，run `…ns3_20260923T143026Z`）的 `access_trace.csv` **逐事件统计**：

| 阶段 | 计数 | 说明 |
|---|---:|---|
| 接入事件总数 | **1200** | = 合法 **1138** + 伪造 **62** |
| ├ RACH 阶段未受理（`collision_fail`） | 350 | 合法 329 + 伪造 21（拥塞下前导码未受理） |
| └ 进入认证环节 | 850 | 前导码受理成功 |
| 　 ├ 通过（`ok`） | 809 | 合法终端接入成功 |
| 　 ├ 拦截（`bad_mac`） | 35 | **盲伪造**被星上 HMAC 拒（`result=fail`） |
| 　 └ 漏检（`ok_missed`） | 6 | **密钥泄露型**伪造通过校验（符合 ≈1−share） |
| 切换事件 | **10736** | ├ 重连确认成功 10735　└ 确认失败 1（计入切换中断；主方案预迁移命中率 1.0 → 不发生 rerach） |

**对账（脚本实测，全部一致）**：

| 指标 | 由 trace 重算 | `metrics.json` |
|---|---|---|
| 合法接入成功率 | 809 / 1138 = **0.7109** | 0.7109 ✓ |
| 伪造终端拦截率 | 35 / (35+6) = **0.8537** | 0.8537 ✓ |
| 伪造终端总数 | 62 | 62 ✓ |
| 假名轮换次数 | = 切换事件数 10736 | 10736 ✓ |

> **为什么这是「方法各阶段」最直接的证据**：它把「RACH → 认证 → 切换 → 兜底」四段**串成一条可核对的链**，
> 每段的通过/拒绝计数都能与聚合指标对账。**且拦截率的分母口径（仅「进入认证环节」的伪造终端）在此可见**——
> 这正是 §2.1 口径的可视化，能挡下评审"为什么不是 35/62"的追问。

### B.4 边界（诚实红线）：哪些能「回放」、哪些只能「示意」

| 内容 | 能/不能 | 处理方式 |
|---|---|---|
| 接入/切换**事件级**结果（何时、哪颗星、中断多久、是否失配/乒乓、业务类型） | ✅ 能回放 | 引擎驱动，标注 `run_id` |
| **逐条消息**握手（msg1/msg2/msg3/msg4、msgA/msgB） | ❌ trace 无消息级记录 | **机理示意图**，页面显式标注「**机理示意，非数据回放**」 |
| T8 提前量生效（话音 +12 / 图像 +4 / 短信 +0 s） | ✅ 能对照 | 开关对照 + trace `service` |
| 预迁移的**内部执行**（上下文推送、星间链路传输） | ❌ 仅结果可见 | 以「命中率 1.0 / 重连额外时延 0 ms」+ 机理示意体现 |
| 星上调度决策过程（guard-channel / Kaufman-Roberts 阈值） | ❌ 仅聚合结果 | 展示 `dp平均高危预留`、`加权阻塞率` 等结果量 |

> ⚠️ **红线**：图元若来自机理推导而非数据，**必须在图上标明「示意」**。国奖「材料真实性」是一票否决项，
> 把示意图伪装成实测数据＝自杀。本方案的硬性约定：**每个数据图元带 `run_id`，每个示意图元带「示意」字样**。

> 分值口径来源：2025 官方附件确认创意组「个人成长」为 30 分；2026 版四维度 30/30/25/15 的拆分来自备赛辅导资料，**建议以官方评审规则原文复核后再定稿**。

### 2.2 答辩（路演）四维度 —— 这才是 demo 的真正考验

1. **学生主体性**（权重最高）→ demo 必须**人人能操作、人人能讲**
2. **逻辑闭环度** → 痛点 → 方案 → 创新 → 验证，前后不得矛盾
3. **落地真实性** → 所有数据**可溯源**、应答务实，**拒绝虚构**
4. **创新与价值高度** → 技术壁垒与价值清晰

**硬性禁区**：夸大成果、虚构数据、回避短板、答辩内容与材料不一致、堆砌自己解释不了的专业术语。

**时间**：5 分钟路演 + 3~~5 分钟问答，**严格卡点、超时扣分**；国赛 PPT 20~~25 页，**减少花哨动画与切换特效**。

## 十、3D 方案深度评估（决策项 · 2026-09-25 补）

### 10.1 商用 / 官方级的「高级」到底来自哪里

| 层面 | 商用 / 官方做法 | 实例 |
|---|---|---|
| 地理数据 | 高分辨率全球影像 + 地形 + 建筑 **3D Tiles，流式按需加载** | STK 的 Geospatial Data Cloud **= Cesium ion Self-Hosted**（付费，需自建服务器/私有云）|
| 传感器与覆盖 | 传感器视场（FOV）体、覆盖品质网格、几何约束（最小仰角） | STK Pro：*Model vehicle and sensor fields of view*、*coverage grids* |
| 轨道与姿态 | 高精度传播、姿态、深空、机动规划、碰撞分析 | STK Premium (Space) |
| 报告 | 100+ 种定制报告；时间动态 3D 环境 | STK |

> **关键结论**：它们的「高级」≈ **数据资产 + 流式服务**，而不是「画得更炫」。**STK 自己不做地球——它买 Cesium ion Self-Hosted**。
> 所以照搬这条路，等于照搬它们的**服务器与采购**，不是照搬它们的渲染。

### 10.2 我们的硬约束（不可谈判 → 排除 Cesium 全功能路线）

Cesium 官方文档明确（已核实）：**3D Tiles / glTF / 地形 / 影像这些静态资源，因浏览器把 `file://` 视作跨域请求，必须通过本地服务器提供**；离线可用的只有「裸椭球体地球」（`EllipsoidTerrainProvider` + `baseLayer:false`）。
→ 而「双击即开」正是我们的验收标准。**结论：Cesium 全功能路线与本项目验收标准在架构上冲突，排除。**

其余约束：断网（零 CDN / 零在线瓦片）、仓库体积（不能塞全球地形影像）、国赛明确「**减少花哨动画**」。

### 10.3 离线可用、值得做的技术清单（按收益 / 成本 / 风险分档）

| 档 | 内容 | 离线风险 | 观感收益 |
|---|---|---|---|
| **T1 必做** | 地球球体 + 经纬网；651 星 `InstancedMesh`（单 draw call）；轨道弧；终端点位按危险度分色；可见性连线 + **仰角掩蔽圈（25°）**；时间轴播放/暂停 | 无 | ★★★☆☆ |
| **T2 强烈建议** | **NASA Blue Marble 真实贴图**（公有领域，已实测可下载）；**大气边缘辉光**（外层大球 + 菲涅尔 shader，高级感的最大来源）；**晨昏线 + 太阳光照**（按仿真历元算太阳方向）；**波束圆锥**（服务星→终端）；程序生成星空 | 无（贴图内联 base64） | ★★★★☆ |
| **T3 增强** | 业务分色（话音/图像/短信）；切换事件回放（trace 驱动）；预迁移时序动画；3D ↔ 指标图 ↔ 时间线多视图联动 | 低 | ★★★★★ |
| **T4 不做** | Cesium 3D Tiles / 全球地形影像（需服务器）；STK 级传感器 FOV 体与覆盖品质网格（专有工具）；三维建筑与真实阴影（数据资产成本）；**浏览器内跑 SGP4**（我们用 Python 预计算，与仿真同源、更准） | — | — |

### 10.4 三个档位（决策表）

| 档 | 内容 | 新增体积 | 离线风险 | 观感 | 工量 |
|---|---|---|---|---|---|

### 10.6 风险与对策（含自动降级）

| 风险 | 对策 |
|---|---|
| **`file://` 下 WebGL 能否上传本地图片作贴图**（Chrome 的不透明源可能让 `texImage2D` 抛 SecurityError） | **一律内联 base64 data URI**（同源，必然可用）——不做任何「外置图片」假设。外置是否可行留待实施阶段实测（需装 `agent-browser`，约 500 MB） |
| 演示机无 WebGL / 驱动异常 | `WebGLRenderer` 探测失败时**自动降级**为 ECharts 版平面机理图（同一份数据，不丢内容） |
| 国赛「反花哨」导向 | 默认**静态视角**；动画仅在点击「播放」时启动；不做镜头飞入/镜头特效 |
| 仓库体积膨胀 | 贴图只留 1 张且降采样；vendor 上限 1.8 MB（CI 断言体积） |

### 10.7 「不如商用高级」这个心结怎么解

- **路线 α（推荐）：换叙事——不拼地球，拼「可溯源的数据证据」**。评审看的是机制与证据，不是地球像素。我们有**双轨互证 + 10 种子 CI + run_id 全溯源**，这是 STK 也给不了的「本项目的证据链」。3D 定位为「讲清几何机理的一屏」。国赛明确反对花哨动画，**克制反而是加分**。
- **路线 β：逼近商用观感**——真实贴图 + 大气辉光 + 晨昏线 + 波束锥（即 3D-B），可达到 satvis / Exosphere 那类开源标杆的「专业感」。代价约 +0.5 MB 与中等工量。

**推荐：3D-B + 路线 α 的叙事**——观感够专业，且不牺牲离线与克制原则。

## 十二、外部对标：同类高级 / 商业 demo 的做法与借鉴（2026-09-25 补）

> 目标：先看"别人怎么做到高级"，再据此**复核我们的决策**，最后列出仍不确定的可选项（§十三）。

### 12.1 三类对标对象：它们的「高级」到底来自哪里

| 类别 | 代表 | 「高级」的本质 | 我们能取的部分 |
|---|---|---|---|
| **A. 商用 / 官方仿真平台** | Ansys STK（原 AGI，NASA／SpaceX／美太空军在用） | **物理引擎 + 付费数据资产**（高分辨率地形影像走 Cesium ion Self-Hosted）+ **一套专业概念体系** | 概念体系可免费借鉴（见 12.1-A）；数据资产不追 |
| **B. 研究论文的「流程可视化」** | ml_paper_visualizer · stanch/pipeline · snej55/pipeline_visualisation · friendmine/aidemo | **把不可见的"方法流程"变成可点、可播、可查的图形** | ★最高价值——与"展示方法各阶段"直接同构（见 12.1-B） |
| **C. 行业实演（应急通信）** | GEXTRECS（EUSPA/GOVSATCOM）· WISECOM（DLR）· ESA SAFE · emergency.lu | **真实情境脚本 + 分阶段演练 + 现场可讲** | 叙事骨架（见 12.1-C） |

#### A. STK 的可迁移之处（概念，不花钱）

- **Coverage Definition Grid（覆盖定义网格）**：可约束到全球／区域／**特定保护区点位**，网格可动态重算。
- **Figures of Merit（品质因数）**：`Percent Satisfied（瞬时）` / `Percent Accumulated Coverage（累积）` / `Age of Data` / `Number of Assets`，且每项都能**瞬时值 vs 时间平均**两种可视化。
- **Access（访问窗口）分析**：卫星↔地面、卫星↔卫星的可见窗，**带最小仰角约束**；输出 Access 时间表。
- **Accumulated Coverage 曲线**：STK 官方示例的读法——"24 h 内能否 100% 覆盖"是星座设计的早期判据（示例中 6 面 ×2 星约 4 h 达 100%）。
- **Interactive models of the operational environment**：不只是模拟系统，而是**可交互的任务环境模型**。
- 免费 Level 1 无时间限制（含 3D 地球可视化 + 地面站访问分析）——**可作为我们的交叉核验参考工具**，但不进 demo（重客户端、非离线单页）。

> **对标结论**：STK 的"高级感"一半来自**概念体系**（我们可白拿：覆盖网格 / FOM / Access 窗 / 瞬时-累积双读法），
> 另一半来自**付费数据与服务器**（不追）。我们其实**天然已有对应物**：场景区域 ↔ 覆盖网格，指标 ↔ FOM，
> 可见窗 ↔ Access，预迁移提前量 ↔ "Age of Data" 的逆向用法。

#### B. 论文流程可视化 —— 与「展示方法各阶段」直接同构（★最重要★）

| 项目 | 核心做法 | 对我们的直接价值 |
|---|---|---|
| `ml_paper_visualizer` | 把论文工作流（采集→预处理→建模→评估）抽成**交互式流程图**；**组件可点击，且每个组件回链到论文对应章节**（Paper Reference） | ★**"组件 ↔ 出处"回链** = 我们的 `run_id` 溯源徽标。应把它从"徽标"升级为**可点击 → 溯源详情侧栏** |
| `stanch/pipeline` | **Sankey + spaghetti 双模式管道图**：列 = 阶段，行 = 时间，线 = 个体；颜色 = 进入／某阶段失败／完成。回答"流动还是停滞、管道多大、变大还是变小、**哪一阶段失败率最高**、**某个个体到底经历了什么**（悬停看路径）" | ★★这正是我们 §一·B.3 **阶段漏斗的最佳视觉范式**（1200 → 拦截 350 / 进入 850 → 通过 809·拒 35·漏 6） |
| `snej55/pipeline_visualisation` | OpenGL 3D 论文云 + **instanced rendering**（单次绘制大量实例） | 印证 651 星用 `InstancedMesh` 是标准做法 |
| `openmr2021-dataviz` | 主张研究输出从"PDF 静态图"升级为**可交互、可探索、面向未来**；配套 Dash 应用随论文发布 | 支撑"交互式成果"是学界公认升级方向 |
| `friendmine/aidemo`（LLM 算子可视化） | **纯 HTML/CSS/JS、零后端**；14 个算子**逐个动画**；每条含 **播放/暂停/重置 + 可调参数 + 实时数据流 + 详细步骤说明** | ★★与我们的架构**完全一致**，且证明"**无 3D 也能把方法流程讲透**" |

> **三点直接采纳**：① 漏斗图改用 **Sankey/spaghetti 式交互**（可悬停追溯单个终端/单个切换的完整路径）；
> ② 溯源从"徽标"升级为"**点击 → 侧栏详情**"（run 标签 + 对照表行 + results 文件 + 该数字的复算公式）；
> ③ 每条机制的"示意"屏采用 **动画 + 播放/暂停/重置 + 步骤说明**（可调参数仅在数据支持时开放，见 §十三-O4）。

#### C. 应急通信行业实演 —— 叙事骨架

| 项目 | 关键做法 | 可借鉴 |
|---|---|---|
| **GEXTRECS**（EUSPA Horizon Europe，GOVSATCOM；2024-02 ~ 2026-01） | 场景脚本：**7.4 级近海地震 + 5G/LTE 完全中断 ≥36 h**；跨国双现场（德国 ISAR 陆地搜救 / 西班牙 CSIC 海上）；演示「动态资源分配」与「网络切换」；配 **Rapid Access Kits**；近 200 人观摩 + 事后问卷 | ★**"真实情境脚本 + 分阶段 + 现场可讲"**的叙事范式 |
| **WISECOM**（DLR，欧委会） | 卫星回传整合 GSM/WiFi/WiMAX/TETRA；**两套系统版本对应灾后不同阶段** | ★**按灾后阶段组织内容**（而非按技术模块） |
| **ESA SAFE** | 演练按 **day 1（应急响应）/ day 2（流行病威胁）** 分阶段推进 | 时间轴推进的演示节奏 |
| **emergency.lu** | 充气卫星天线 + TV 白频谱 + 无人机中继 → "vertical connectivity" | 一句话主线（我们有：终端直连 → 星间预迁移） |

> **采纳**：L0 叙事改用**灾后时间线**（0 h 公网全瘫 → 数小时内建立直连 → 持续运营），三机制挂到时间轴上。
> **相对优势（重要）**：行业实演的情境是"设定"的，而我们的场景参数**本身就是仿真输入**——
> 汶川坐标 `31.0083°N / 103.5833°E`、`1200` 终端、`1 s` 内涌入、`10 ms` 时间片仅 `4` 个前导码、伪造比例 `5%`、密钥泄露 `15%`——
> **全部可从 `sim/scenario.py` 直接读出，无需编造**。这是国奖"材料真实性"上我们比 PPT 型项目更硬的地方。

### 12.3 决策再确认（逐条复核）

| # | 原决策 | 对标后的复核 | 是否修正 |
|---|---|---|---|
| 1 | 主形态 = 离线单页 HTML | aidemo 证明**纯前端单页可完整承载"逐阶段动画"**；STK 是重客户端（不可比）；GEXTRECS 是现场实演（更重） | ✅ **维持**，但**录屏备份的必要性上升**（行业实演都留视频记录） |
| 2 | 3D 取 B（仅一屏） | STK 的高级 = 数据资产（不追）；aidemo/snej55/stanch 证明**无 3D 也能讲透流程** | ⚠️ **可降级**：3D 变为"锦上添花"而非关键路径——见 §十三-O1 |
| 3 | 阶段漏斗 = 最强抓手 | 被 `stanch/pipeline` 范式强力支持，且我们有真实漏斗计数 | ✅ **维持并升级**为 Sankey/spaghetti 交互式 |
| 4 | 溯源 = 三要素徽标 | 被 `ml_paper_visualizer` 的 Paper Reference 支持 | ✅ **升级**为"可点击 → 侧栏详情" |
| 5 | 事件回放粒度 | ★**新增实测**：trace 含完整 `t_s` 时间轴（`wenchuan_storm2` = 11936 事件 / 3560 s / 3.4 事件/秒）→ **可做真回放**；全量 7 字段序列化仅 **471 KB/场景**，15 s 分箱仅 **2.2 KB**（218× 压缩） | ⚠️ **需你选**——见 §十三-O2 |
| 6 | 数据真实性以"不编造"为底线 | 行业实演用情境设定；我们的场景参数**直接来自 `sim/scenario.py`** | ✅ **维持并强化**：L0 直接展示"输入参数卡"（可溯源的叙事） |

| 8 | 不出在线部署版 | 与"双击即开"一致 | ✅ **维持** |

> **体积复算（实测，非估算）**：`demo/` = vendor 1.64 MB（ECharts 1.03 + Three r147 0.61）+ 贴图 ≈0.4 MB（3D-B 时）
> + 数据（4 场景全量事件 ≈1.9 MB **或** 仅聚合 ≈30 KB）→ **总计 2.0 ~ 4.0 MB**，仍在上限内。
> 若选"仅 1 个主场景全量 + 其余聚合"，数据 ≈0.5 MB，总计 ≈2.6 MB。
