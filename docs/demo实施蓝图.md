## 一、总架构与数据流

```
results/*.json  ┐
对照表 §2/§3/§3.1 ├─→ demo/tools/build_demo_data.py ─→ demo/data.js ─→ demo/index.html
trace CSV        │        （Python 3.13 venv）          （只读，零计算）    （双击即开）
sim/scenario.py  ┘
```
**铁律**：页面**只读** `data.js`，绝不在前端硬编码数字；数值变化只改数据源 + 重跑脚本。

**技术选型（定稿）**：
- **原生 JS**（无框架）
- **ECharts 5.5.1**（v1，已校验）——交互图表
- **原生 WebGL**（零库自写）——651 星 3D 星座（Three.js 已备但**不依赖**，仅作 3D-B 观感增强的备选）
- **零 CDN / 零构建 / 零后端**

**全局交互约定**：
- 顶部固定「**对比开关**」：本方案 ↔ Rel-17 基线（切换时所有图表同步）
- 每个数据图元带 `data-metric` / `data-value` / `data-runid`（自检脚本据此断言）
- 每个示意图元带「**机理示意，非数据回放**」水印
- 每屏右下「**三要素徽标**」：`run_id` + 对比基线 + 一句话结论（可点击 → 溯源侧栏）

## 二、`build_demo_data.py` 数据契约（字段级）

| data.js 字段 | 内容 | 数据来源（**唯一权威**） | 复算方式 |
|---|---|---|---|
| `meta.generated_at` | 生成时间 | — | 运行时 |
| `meta.sources` | 每个指标的溯源（文件 + 章节） | 见各行 | 硬表 |

| `funnel{}` | 阶段漏斗计数 | `data/sim/runs/<storm2 ns3>/access_trace.csv` | 按 `auth_result` × `result` 分组计数 |
| `timeline{}` | 事件回放（**混合粒度**：1 主场景全量 + 其余 15 s 分箱） | 同上 trace | 全量取 `t_s/event_type/result/service/value_ms`；分箱聚合 |
| `crossval{}` | 双轨对照 4 场景 × 10 指标 | 对照表 §2（Python）/ §3（ns-3）/ §3.1（T8） | 解析 markdown 表格 |

| `priority{}` | 生存优先（high/med/low + 加权阻塞率） | `results/subgroup_metrics.json` | 直接读 |
| `ablation{}` | 三阶段消融边际 | `results/ablation*.json` / `summary` | 直接读 |
| `sensitivity{}` | 3 组曲线（ho_lead / ephem_err / share） | `results/敏感性分析_20260903.json` | 直接读 |
| `multiseed{}` | 10 种子 CI + Rel-17 三配置 | `results/多种子统计_storm2_10seed_20260923.json` | 直接读 |
| `resources{}` | **I-12 资源效率** | `sim/protocol.py`（步数/`RACH_SLOT_UNITS`）+ trace 事件数 + `config.AUTH_CPU_DERATE` | 现算（见 §三 S17） |
| `burst{}` | **I-15 抗冲击** | `results/experiment_ledger.json`（`burst_intensity` 分组）+ 对应 run 的 metrics | 现算 |
| `limits{}` | 已知局限 + TRL 定位 | README §9.3/§9.6 + 审计报告 §二-B | 硬表 |
| `evidence{}` | 证据索引（run_id → 文件 → 复算公式） | 以上汇总 | 硬表 |

**体积预算**：`constellation` ≈172 KB + `timeline` ≈0.5 MB（混合）+ 其余 ≈100 KB → **`data.js` ≈0.8 MB**（上限 4 MB，充裕）。

## 五、关键技术实现要点（已定选型）

| 议题 | 决策 | 理由 |
|---|---|---|
| 图表实现 | **ECharts**（已本地化）；**关键数值不依赖图表渲染**，而由 `data-metric` 独立承载 | 图表只负责"看"，断言只认 DOM 属性 —— 两者解耦，图挂了也不影响数字正确性 |
| 漏斗（I-05） | 优先 **ECharts `sankey`**；若观感/性能不足，回退**手写 SVG**（约 80 行） | sankey 原生支持悬停追溯 |
| 651 星（I-03） | **原生 WebGL + InstancedMesh 思路**（12 帧坐标线性插值） | 已实测 `file://` 下 WebGL 可用；零库依赖 |
| 30× 量级差（I-01） | **双面板**（主图 + 放大插图）；备选对数轴 | 截图中实测 12.06 与 381.0 同轴不可读 |
| 事件回放 | **混合粒度**：主场景全量（可逐事件查询）+ 其余 15 s 分箱 | 体积 0.5 MB vs 全量 1.9 MB |
| 溯源侧栏（O3） | 点击数字 → 右侧抽屉：`run_id` + 对照表行 + 文件路径 + 复算公式 | 学 `ml_paper_visualizer` 的 Paper Reference |
| 「示意」水印（I-06） | 统一 class `.schematic`，自检脚本断言**每个** `.schematic` 含"示意"字样 | 诚实红线，可自动化守住 |
| 3D 降级 | WebGL 探测失败 → 自动换成 ECharts 平面机理图 | 演示机异常保底 |
