## 一、审计方法（可复用对账链）

对每一个断言，沿**四层证据链**回溯，任一层断裂即判不合格：

```
demo 页面文字/图元
   ↓ ① 键名与取值
data.js（构建产物，键 → 值）
   ↓ ② 构建时断言（build_demo_data.py 5 类）
results/*.json（实测指标）  ←→  docs/双轨交叉验证对照表.md（权威口径）
   ↓ ③ 语义核对
sim/*.py（Python 轨实现）  ←→  .ns3_ref/leo_access.cc（ns-3 轨实现，须镜像）
```

**关键纪律**：数值一致 ≠ 语义一致。本次审计的重点正是**「数字对、但解释错」**这类缺陷。

### 3.2 ❌ 与仿真矛盾的项（硬伤）

**A5 甘特图右下角原文字**：

> 「↑ **这 381 ms 就是「中断」的来源**」

**为什么错**：
1. **概念混淆**：381.0 ms 在对照表 §6 中是 `predictive_nopremig`（关闭预迁移）的**切换总时延**，**不是中断**。
2. **与归因更正直接矛盾**：对照表 §6 明确「消融臂实测两者**切换中断完全相同（均 ≈0.01 ms）**」——关闭预迁移**并不会**产生 381 ms 的中断。
3. **屏内自相矛盾**：同一屏右侧 tile 写着「中断归零来自**先建后断的重叠窗**，与预迁移机制正交」——甘特说「381 ms 是中断来源」，tile 说「中断归零与预迁移无关」，两者打架。
4. **机理错误**：关闭预迁移的对照臂**同样享有 20 s 提前量与先建后断**（`protocol.py:714-718`：`predictive` 与 `predictive_nopremig` 共用 `ho_lead_eff`），故 381 ms 的重连**落在提前量窗口内完成**，旧链尚未丢失 → 中断仍 ≈ 0。

**已修正为**：「↑ = 切换总时延（非中断）」＋「两臂均含 20 s 提前量 → 中断均 ≈ 0」。

### 3.3 ⚠️ 画了不发生的分支

**A5 梯形图原文字**：「失配→完整重连 381 ms」

**为什么是问题**（三条独立证据）：
1. `protocol.py:862`：`do_premigrate = P["pre_migrate"] and policy == "predictive"`；
2. `protocol.py:863-866`：迁移写入 `sat_ctx[cand]`（`cand` 即本次执行的目标星），命中判定读 **同一个** `cand` → **`has_ctx` 恒真**；
3. 实测：`results/wenchuan_metrics.json` 的 **`切换重连额外时延_ms = 0.0`**、多种子统计 `预迁移命中率 = 1.0`（10 种子 σ=0）→ **主方案从未发生过 rerach**。

ns-3 侧完全镜像：`leo_access.cc:1012` `doPreMigrate = (g_preMigrate!=0) && (g_hoPolicy=="predictive")`；`:1096-1097` 迁移与命中同为 `cand`。**双轨皆然**。

**处置**：该分支改为**防御性标注**——「兜底：失配→完整重连（防御性；主方案命中率 1.0，双轨实测不触发）」，并**半透明弱化**（`opacity=0.5`），不再呈现为主流程的一支。

> **连带建议（叙事口径）**：「失配兜底」在 `docs/最终方案_融合版.md §3` 等处表述为「已实现」。**实现**属实（代码分支存在），但**主方案下不可达**（同源迁移必然命中）。答辩/材料中宜表述为「**防御性设计**：若未来引入星间失配（如迁移目标星选择与执行星解耦），该路径即启用」，避免被追问「命中率 1.0 时该机制是否真的起作用」。另：`docs/demo制作方案.md` 中「确认失败 1 → 触发失配兜底 rerach」亦不实（`confirm_fail` 仅计入中断，见 `protocol.py:907-913`），已一并更正。
